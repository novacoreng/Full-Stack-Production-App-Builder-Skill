# Engineering Standards Baseline

Use standards as verification references, not as claims of certification.

## Application security
- OWASP Application Security Verification Standard (ASVS) 5.0.0: use requirement identifiers when mapping technical security controls.
- OWASP Software Assurance Maturity Model (SAMM): use as a maturity/process lens where appropriate.

## Secure software development
- NIST SP 800-218 (SSDF) 1.1 is a finalized baseline.
- NIST SP 800-218 Rev. 1 / SSDF 1.2 was published as an initial public draft in December 2025; if using it, label it as draft and verify the current status before relying on it as a finalized standard.
- NIST SP 800-218A provides a generative-AI-specific SSDF community profile.

## Accessibility
- For web products, use WCAG 2.2 as the current W3C Recommendation baseline unless the product's applicable requirements specify otherwise.
- Test keyboard access, focus, labels, semantics, contrast, zoom/text scaling, motion, error identification, and assistive-technology behavior as applicable.

## General rule
Standards are baselines for engineering verification. They do not by themselves establish legal compliance, certification, or suitability for every jurisdiction/product.
